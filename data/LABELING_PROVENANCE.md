**All three passes (A, B and the 30-row third pass) are the same model.** Their agreement

**Gaps still open after v2**, reported by the v2 labelers:
- an outbound message with two questions, where a bare "yes" can answer either;

- a message whose outbound text is empty (1 row, labeled from the reply alone);
- asking for an "advisory session" without giving a time;
- claiming promised material (a video) rather than a call.

## Procedure

1. **Freeze the guide.** Hash above. Gaps found during labeling were written down for a
   later revision, not fixed mid-run (see *Guide gaps*).
2. **Pass A.** A sub-agent with a clean context labeled all 164 rows in a fixed random order
   (seed `20260927`), reading only the guide and the already-pseudonymized reply plus the last
   outbound message. Output per row: label, explicit opt-out flag, confidence and a reason of
   at most 12 words in the labeler's own words.
3. **Pass B.** A second sub-agent with a clean context did the same in a different order (seed
   `20260928`), without access to pass A.
4. **Reconciliation.**
   - When A = B, that label is kept, with the lower of the two confidences.
   - When they differ, a third clean-context sub-agent looked only at the disputed rows and the
     two candidate labels. It applied the guide's priority rule only when the message
     genuinely fits both classes.
   - Anything else is marked unresolved and keeps label A with **low** confidence.
   - Every disputed row is flagged `disagreement = yes`.

## Human verification

A random sample of 30 rows (seed `20260929`) was prepared for the project owner, **without
any Claude label shown**. **The project owner then decided not to label it himself**, so
**rows verified by a person remain 0**. The same 30 rows were re-labeled instead by a third,
fresh Claude pass (see *Version 2*). That is a consistency check within one model, not a
check by a person.

## Limitations

- **These are a model's labels, not a person's.** They can be consistently wrong in ways
  that no metric in this repository will reveal.
- **If the evaluated classifier is also Claude, agreement can be inflated by shared biases.**
  The classifier should use a different model or approach, or declare the circularity next
  to every number (see `DECISION.md`).
- **The A–B agreement is between two runs of the same model family.** 95.7 % measures
  consistency, not correctness. Two runs sharing the same blind spots agree easily.
- **Independence of A and B was enforced by instruction, not by isolation.**
  - Each sub-agent had a clean context and was told to read only the guide and the dataset.
  - Both wrote helper scripts to a shared scratch folder, which the other could technically
    have opened.
  - File access was not audited.
- **Deviation from the requested procedure.** Pass A was meant to be run by the orchestrating
  session. It ran in a clean sub-agent instead, for two reasons:
  - that session would otherwise have printed customer text into the conversation;
  - it had authored label proposals the day before, which would have anchored it.
- **Pseudonymization changes the text.** Names, phones, brands and some common words are
  replaced by markers. Labels were assigned on the scrubbed text.
- **Few-shot examples** for any classifier must never come from rows or leads in the
  evaluation set (4 leads have two different replies).

## Guide gaps found while labeling (for the next guide version)

1. **Short yes, or an emoji, answering a question in the outbound message.** The guide only
   covers "yes without context".
2. **"Busy right now" versus "explains why they missed the call".** The boundary between
   `pospone` and `sin_intencion` is unwritten.
3. **A message that is only a channel preference** ("here", "by text?") becomes
   `prefiere_escrito` without an explicit call refusal. About 12 rows.
4. **Temporary versus permanent call refusal** (travelling, busy period).
5. **Partial "not applicable" cases**: a child outside the age range, a baby not yet born, a
   non-parent asking about a product. Only "no baby" is covered.
6. **Direct purchase intent and pre-filled landing messages** have no class of their own and
   are absorbed into `pide_informacion`.
7. **Confirming an appointment the company already set**: no class fits.
8. **"Cancel" without saying what**: not treated as an opt-out.
9. **The guide mentions a `nota` column** that the label file format does not have.
